# Whisperwing

Локальный desktop-ассистент для рабочих созвонов на Python. Слушает системный звук, распознаёт речь в реальном времени и по горячей клавише объясняет контекст разговора через LLM — полезно, когда на созвоне всплывает термин из незнакомой области (медицина, дизайн и т.п.), а тормозить встречу вопросами не хочется. Также умеет объяснять и решать задачи по содержимому выделенной области экрана через vision-модель.

Инструмент прозрачен для собеседников — предполагается, что участники созвона знают, что используется ассистент. Это контекстный помощник, а не средство скрытой подсказки.

## Возможности

- Захват системного звука без виртуальных аудиокабелей (WASAPI loopback)
- Нарезка речи по паузам (Silero VAD), а не по фиксированному времени — сохраняет цельность фраз
- Распознавание речи в реальном времени (faster-whisper), с настраиваемым словарём терминов под конкретную область
- Объяснение контекста последних минут разговора по хоткею через LLM
- Выделение области экрана мышью — объяснение или решение задачи через vision-модель
- Абстракция над LLM-провайдером: локальный (Ollama) или облачный (Claude API), переключается одной переменной окружения
- Overlay-панель поверх остальных окон: перетаскиваемая, с регулировкой прозрачности

## Архитектура

```
Динамики (WASAPI loopback)
        │
        ▼
  recorder (сырой поток, активен только когда прослушивание включено)
        │
        ▼
  VAD-сегментер (Silero VAD)
  нейросеть определяет речь/тишину по кадрам,
  режет звук по паузам, а не по таймеру
        │
        ▼
  faster-whisper
  распознаёт каждый сегмент речи
        │
        ▼
  ConversationBuffer
  скользящее окно последних N минут
        │
        ├── хоткей / кнопка "Объяснить" → LLM объясняет контекст разговора
        │
        └── хоткей / кнопка "Экран" → выделяешь область мышью →
            скриншот + контекст разговора → vision-LLM объясняет/решает

Всё отображается в overlay-панели (PyQt6): текущий транскрипт,
последний ответ, статус, элементы управления.
```

## Стек

| Компонент | Технология |
|---|---|
| Захват звука | pyaudiowpatch (WASAPI loopback) |
| Детекция речи | silero-vad (нейросеть, PyTorch CPU) |
| Распознавание речи | faster-whisper |
| Захват экрана | mss, Pillow, выделение области — tkinter |
| LLM (текст и vision) | Ollama (локально) или Claude API, через общий интерфейс |
| UI | PyQt6 — overlay-панель |
| Хоткеи | keyboard — глобальный хук на уровне ОС |
| Управление зависимостями | Poetry |

## Установка

```bash
poetry install
```

### Ollama (локальный вариант)

```bash
ollama pull qwen2.5:7b   # текстовая модель
ollama pull llava:7b     # vision-модель для скриншотов
```

### Claude API (опционально)

Ключ — на console.anthropic.com.

### .env

```
LLM_PROVIDER=ollama
ANTHROPIC_API_KEY=
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b
OLLAMA_VISION_MODEL=llava:7b
```

## Запуск

```bash
poetry run whisperwing
```

| Действие | Хоткей | Кнопка |
|---|---|---|
| Вкл/выкл прослушивание | Ctrl+Shift+L | Слушать |
| Объяснить последние минуты | Ctrl+Shift+E | Объяснить |
| Выделить область экрана | Ctrl+Shift+S | Экран |

Прослушивание выключено по умолчанию — включается перед созвоном. Хоткеи глобальные, работают вне зависимости от фокуса окна.

## Технические проблемы и решения

Ресемплинг аудио. Whisper при передаче сырого массива данных ожидает 16кГц, а WASAPI отдаёт звук на частоте устройства (обычно 48кГц). Без явного ресемплинга модель интерпретировала аудио так, будто оно длится втрое дольше реального, что почти полностью ломало распознавание, при этом сами аудиофайлы звучали нормально, потому что в заголовке wav-файла частота была указана верно. Диагностировалось через сравнение поведения на сохранённых debug-чанках против того же аудио в live-пайплайне.

Фиксированная нарезка звука (по 8 секунд) обрывала фразы на середине слова и провоцировала Whisper на галлюцинации на тишине и шуме. Заменена на детекцию речи через Silero VAD — небольшую нейросеть, которая точнее классической энергетической эвристики (webrtcvad) отличает речь от музыки и фонового шума и режет звук по естественным паузам.

Слабое следование инструкциям у открытой vision-модели. llava игнорировала системный промпт про язык ответа и начинала галлюцинировать при составных инструкциях («опиши и ответь на русском»). Решение — двухэтапный пайплайн: llava только дословно расшифровывает содержимое скриншота (простая, механическая задача, с которой справляется хорошо), а затем текстовая модель (qwen2.5:7b, заметно лучше следует инструкциям) на основе этой расшифровки формулирует связный ответ на русском.

Threading и GUI event loop. Qt требует, чтобы UI жил в главном потоке со своим event loop, а аудио-пайплайн изначально был написан вокруг простого блокирующего цикла в main(). Переход на overlay потребовал развернуть архитектуру: GUI стал главным потоком, вся аудио- и LLM-логика ушла в фоновые daemon-потоки, связь с UI — через потокобезопасные Qt-сигналы (pyqtSignal).

## Структура проекта

```
src/
  config.py              # все настройки в одном месте
  audio_capture.py        # захват звука с loopback-устройства
  vad_segmenter.py        # нарезка звука на фразы по паузам (Silero VAD)
  transcriber.py           # faster-whisper: распознавание речи
  conversation_buffer.py   # скользящий буфер транскрипта
  screen_capture.py         # выделение области экрана + скриншот
  signals.py                 # Qt-сигналы для связи фоновых потоков с UI
  actions.py                  # общая логика для хоткеев и кнопок overlay
  overlay.py                   # overlay-панель (PyQt6)
  hotkeys.py                    # регистрация глобальных хоткеев
  main.py                        # сборка пайплайна, Qt event loop
  llm/
    base.py                        # интерфейс LLMClient и системные промпты
    ollama_client.py                 # реализация через Ollama (текст и vision)
    anthropic_client.py               # реализация через Claude API (текст и vision)
    factory.py                         # выбор провайдера из .env
```

## Настройка под свою область

WHISPER_INITIAL_PROMPT в config.py — список терминов, которые Whisper ожидает услышать. Расширяется под конкретную область (медицина, дизайн, специфика продукта) — заметно улучшает распознавание англицизмов и аббревиатур, которые иначе транскрибируются "на слух" русскими буквами.
